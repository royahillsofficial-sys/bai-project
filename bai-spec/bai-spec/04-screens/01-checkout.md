# Shared checkout · CO-1 … CO-6 (build this before any service)

## Prompt for Cursor
> Build the shared checkout used by every Pay service. StepIndicator: Review → Pay → Receipt.
> **CO-1 Review your payments:** PageHeader "Review your payments". Cart table (Dept, Ticket No., Name, Tax type, Description, Amount, Remove). Remove is shown only when `allowRemoveNonDelinquent` is true and the row is not delinquent. A delinquent row shows a shield and "Paid oldest first" and has no Remove. Total row. "Clear cart" (ghost, confirm inline, never `confirm()`). "Add another payment" link → Service home. Existing hCaptcha HumanCheck inline above the button. Primary: "Choose how to pay" (disabled until human check ok and cart not empty). Empty cart → EmptyState. `checkoutNotices` from the county render above the table.
> **CO-2 Choose how to pay:** two PaymentMethodChooser cards: "eCheck — no processing fee" showing total; "Credit or debit card" showing amount + fee + total. The fee is `cardFee.percent` and/or `cardFee.flat` (fall back to `cardFeePercent`). Primary: Continue. Never render card-number fields. Card payment is always a redirect.
> **CO-3 Card summary:** FeeSummary (payment amount, card processing fee, total due) + note "Card payments are processed securely by {config.processor}. The county never stores your card details." Primary: "Continue to secure payment" (in demo, simulate redirect then go to CO-5).
> **CO-4 eCheck:** ECheckForm — Name on check when `eCheckNameOnCheck` is true; Routing number + Confirm; Checking account number + Confirm; "Hide numbers" switch (masks inputs). When `validateRouting` is true, "Verify routing number" shows the bank name and asks "Is this your bank?" before authorize is enabled (demo: any 9 digits other than 000000000 = "First Example Bank"). CheckPreview SVG of a check that highlights the routing (9 digits, left) and account (middle) zones as the user types into each field. InlineNotice warn: "Use the numbers from a check, not a deposit slip." Disclosure: "A $35 fee (config.returnedCheckFee) applies to returned payments." Checkbox "I authorize {county} to debit this account for $X". Primary: "Authorize payment".
> **CO-5 Receipt:** success banner "Payment received", info grid (Payment type, Payment date, Reference no., Transaction no., Amount paid, Processing fee, Total applied to bill), line-items table. The receipt says the receipt was emailed to the stored address. Buttons Print (existing print styles, county letterhead), Resend email, Make another payment. Clear the cart after success.
> **CO-6 Payment failed:** InlineNotice danger with reason, buttons "Try again" and "Use another method". Cart kept.
> Use only tokens, classes and components from /bai-spec/00 and /bai-spec/03. Add as new <section class="screen"> blocks in index.html; register routes in ROUTES. Include loading, empty and error states. Mobile: tables become stacked cards under 720px.

## Acceptance
Same checkout reached from RE, PP, Prepay, Business license, Utilities, Consumer tax, Pet tags, Mineral.
